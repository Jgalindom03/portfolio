    TU DEMO EN 3 MINUTOS

    Una historia fácil de enseñar.

    Un correo entra. Los agentes buscan contexto. Una persona valida la respuesta y el sistema la recuerda.

    1. 01
      Empieza por las alertas del vehículo

      Resuelve el primer correo. DB busca precedentes, RAG consulta la guía y API descubre la configuración. Abre las evidencias de cada agente.

    2. 02
      Revisa, corrige y valida

      Edita el borrador si quieres y pulsa «Validar y guardar». Verás la actualización del CRM simulado y la nueva memoria validada.

    3. 03
      Haz visible el aprendizaje

      Pulsa «Repetir caso». DB recuperará la solución aprobada y los otros agentes no necesitarán intervenir.

    4. 04
      Enseña también los límites

      Prueba la consulta documental, el servicio no disponible o un correo propio. Si falta información, el caso se deriva a una persona.

    Este recorrido conjunto es una propuesta de POC. El proyecto original utiliza DB y RAG en el gestor de tickets y ofrece API como asistente separado.
    PRUEBA TU PROPIO CASO

    Nuevo correo de prueba

    Prueba recuperar una contraseña, crear una geocerca o revisar alertas de velocidad del vehículo LL-204. Para simular un fallo de API, usa LL-305 y «servicio no disponible». Otras consultas se derivan a revisión humana.
